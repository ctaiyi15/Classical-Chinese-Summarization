# Classical-Chinese-Summarization

This repository contains experiments for classical-to-modern Chinese processing, with a current emphasis on:

- round-trip translation from modern Chinese to English and back to modern Chinese
- automatic evaluation of round-trip fidelity
- baseline summarization notebooks and utilities

Reference paper:
- [Classical Chinese Summarization](https://arxiv.org/abs/2308.00240)

## Typical Workflow

1. Add or sync raw bilingual data into `data/raw/<corpus>`.
2. Run translation into `data/processed/translated/<corpus>`.
3. Run back-translation into `data/processed/translated_back/<corpus>`.
4. Run evaluation scripts to generate CSV/JSON/Markdown summaries.
5. Generate summaries into `data/processed/summary/<corpus>` if needed.
6. Run `python3 scripts/clean_summary_preambles.py` to create cleaned summaries under `data/processed/summary_clean/<corpus>`.
7. Inspect `summary.md` for quick reporting and `corpus_metrics.csv` / `file_summary.csv` for deeper analysis.


## Data Convention

Each text unit is stored in a directory that typically contains:

- `source.txt`: classical Chinese source text
- `target.txt`: modern Chinese reference text
- `bitext.txt`: paired display of source and target

For round-trip translation:

1. `data/raw/<corpus>/.../target.txt` is treated as the original modern Chinese reference.
2. `data/processed/translated/<corpus>/.../target.txt` stores the English translation.
3. `data/processed/translated_back/<corpus>/.../target.txt` stores the back-translated modern Chinese output.

The evaluation scripts compare:

- original modern Chinese: `data/raw/.../target.txt`
- round-trip output: `data/processed/translated_back/.../target.txt`

## Translation Workflow

Core translation utilities live in [src/translation.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/src/translation.py) and use `googletrans`.

Main functions:

- `translate(source_path, src_lang, dest_lang)`
  - translates one `target.txt`
  - returns elapsed time, line count, and translated lines
- `one_way_translate(input_root, output_root, source_lang, target_lang)`
  - recursively scans `target.txt` files
  - skips files that already exist in the output directory
  - preserves relative paths under the destination root

Example round-trip entrypoint:

- [src/round_trip.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/src/round_trip.py)

It currently demonstrates:

- `zh-cn -> en` into `data/processed/translated/<corpus>`
- `en -> zh-cn` into `data/processed/translated_back/<corpus>`

## Evaluation

### 1. Existing ROUGE Metrics

[models/evaluation/rouge.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/models/evaluation/rouge.py) contains:

- `rouge_1`
- `rouge_2`
- `rouge_l`

### 2. Additional Fidelity Metrics

[models/evaluation/metrics.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/models/evaluation/metrics.py) adds:

- `chrF`
- `bleu`
- `edit_similarity`
- `length_ratio`
- `embedding_similarity` (optional, requires extra dependency)
- `score_all`

These metrics are intended to give a broader view of round-trip quality than ROUGE alone.

### 3. Single-Corpus Evaluation

Use [scripts/evaluate_round_trip.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/scripts/evaluate_round_trip.py) to evaluate one corpus.

Default configuration evaluates:

- source: `data/raw/晋书`
- back-translation: `data/processed/translated_back/晋书`
- output: `data/processed/evaluation/晋书_round_trip`

Run:

```bash
python3 scripts/evaluate_round_trip.py
```

Optional arguments:

```bash
python3 scripts/evaluate_round_trip.py \
  --source-root data/raw/晋书 \
  --back-root data/processed/translated_back/晋书 \
  --output-root data/processed/evaluation/晋书_round_trip
```

Outputs:

- `line_metrics.csv`
- `file_summary.csv`
- `summary.json`
- `summary.md`

### 4. Multi-Corpus Evaluation

Use [scripts/evaluate_all_round_trip.py](https://github.com/ctaiyi15/Classical-Chinese-Summarization/tree/main/scripts/evaluate_all_round_trip.py) to evaluate every corpus that has:

- raw modern Chinese references under `data/raw`
- back-translated files under `data/processed/translated_back`

Run:

```bash
python3 scripts/evaluate_all_round_trip.py
```

Default output directory:

- `data/processed/evaluation/all_round_trip`

Generated files:

- `corpus_inventory.csv`
- `corpus_metrics.csv`
- `line_metrics.csv`
- `summary.json`
- `summary.md`

## Summarization Notebooks and Baselines

## mT5 Segmented v2 Baselines

The repository now keeps two explicit mT5 baselines over `data/segmented_v2`.
Both use article-level train/test splitting, read chunk-summary pairs from
`segment_sum_concat.txt`, remove summary targets longer than 300 words, and
train `google/mt5-small` with CUDA when available.

See [`EXPERIMENTS.md`](EXPERIMENTS.md) for the detailed experiment log.

### EN -> EN Summarization

- Task: English translated chunk -> English summary line.
- Source field: `translation:` in `data/segmented_v2/**/segment_sum_concat.txt`.
- Target field: `summary:` in `data/segmented_v2/**/segment_sum_concat.txt`.
- Data directory: `data/mt5_en2en_segmented_v2/`.
- Scripts:
  - `scripts/prepare_mt5_en2en_segmented_v2.py`
  - `scripts/train_mt5_en2en_segmented_v2.py`
  - `scripts/evaluate_mt5_en2en_segmented_v2.py`

Existing legacy scripts are still kept for compatibility:

- `scripts/prepare_mt5_segmented_v2.py`
- `scripts/train_mt5_segmented_v2.py`
- `scripts/evaluate_mt5_segmented_v2.py`

### CC -> EN Direct Summarization

- Task: Classical Chinese chunk -> English summary line.
- Source field: `original:` in `data/segmented_v2/**/segment_sum_concat.txt`.
- Target field: `summary:` in `data/segmented_v2/**/segment_sum_concat.txt`.
- Data directory: `data/mt5_cc2en_segmented_v2/`.
- Scripts:
  - `scripts/prepare_mt5_cc2en_segmented_v2.py`
  - `scripts/train_mt5_cc2en_segmented_v2.py`
  - `scripts/evaluate_mt5_cc2en_segmented_v2.py`

The CC -> EN preparation script found exact classical Chinese chunk text in all
409 `segment_sum_concat.txt` files. No fallback approximate chunk alignment was
used.

Current 10-epoch CC -> EN result from
`outputs/mt5-cc2en-segmented-v2-epoch10/eval_results.json`:

| Level | ROUGE-1 | ROUGE-2 | ROUGE-L |
| --- | ---: | ---: | ---: |
| Chunk | 0.143 | 0.017 | 0.115 |
| Article | 0.215 | 0.030 | 0.138 |

Current 10-epoch CC -> EN sampling rerun from
`outputs/mt5-cc2en-segmented-v2-epoch10-sampling/eval_results.json`:

| Level | ROUGE-1 | ROUGE-2 | ROUGE-L |
| --- | ---: | ---: | ---: |
| Chunk | 0.243 | 0.033 | 0.135 |
| Article | 0.360 | 0.078 | 0.154 |

Sampling with `temperature=0.8`, `top_p=0.9`, `top_k=50`,
`no_repeat_ngram_size=3`, and `repetition_penalty=1.2` improves ROUGE for both
pipelines and removes the rough repetition signals measured by
`generation_stats.json`. The sampling outputs are much shorter than the gold
summaries, so these improvements should be checked qualitatively for coverage.

### Summary Outputs

The repository currently distinguishes between two summary directories:

- `data/processed/summary/`
  - original generated summaries
  - may contain LLM-style preambles such as:
    - `Based solely on the provided text, here is a summary:`
    - `Based strictly on the provided text, ...`
    - `### Summary of ...`
- `data/processed/summary_clean/`
  - cleaned summaries with these preambles removed
  - preserves the original directory structure and leaves the original summaries untouched

To generate cleaned summaries, run:

```bash
python3 scripts/clean_summary_preambles.py
```

Default behavior:

- input: `data/processed/summary`
- output: `data/processed/summary_clean`

Generated report files:

- `data/processed/summary_clean/cleanup_report.csv`
- `data/processed/summary_clean/cleanup_report.json`

The cleaning script only removes preamble-like text at the beginning of the file and does not rewrite the main summary content.

## Environment Notes

The repository currently does not maintain a complete `requirements.txt`. Based on the current code, you will likely need at least:

```bash
pip install googletrans==4.0.0rc1
```

If you want to use optional embedding similarity from `metrics.py`, you will also need:

```bash
pip install sentence-transformers
```


## Notes for Contributors

- The directory structure matters: scripts rely on matching relative paths ending in `target.txt`.
- Evaluation is reference-based and assumes `data/raw/.../target.txt` is the modern Chinese gold text.
- Missing back-translated files are surfaced in the generated summaries and affect coverage metrics.
- If you are working with summaries, prefer `data/processed/summary_clean/` for downstream use when you want to avoid LLM-generated preambles.
